# ShareTrace — 国家队 ETF 份额足迹

名字取自「份额的足迹」：把 57 只「国家队曾出现在前十大持有人」的 ETF 的日度份额变化折算成金额，画到 43 个标的指数的 K 线上，标出买卖点。

- 今日：57 只合计净申赎 + 一句话结论 + 近 5/20 日 + 今日信号（带历史强度排名）+ 近 20 个交易日信号点阵与清单
- 指数：43 个标的按大类分组的列表（固定顺序：宽基按成分股市值、行业按指数代码），点进去是单个指数的 K 线、买卖点、信号明细、成分 ETF（含当日 Δ 份额）
- 资金流：月度合计柱状图、年度汇总、最强/最弱月、逐日 CSV
- 口径：算法、数据源、已知限制

纯静态，无后端、无外链、无运行时框架；ECharts 只在详情页加载。

## 视觉

taste-skill app 路线 **data-terminal**（2026-10-26 抽签，seed 511257246）：深色研究终端，卡片比页面底色更深、层级靠明度；数字全部 IBM Plex Mono 等宽、符号写在数字里；选中态统一是 1px 的朱红细线；朱红同时是今日与「国家队在场」的唯一数据色相，涨红跌绿只留给 K 线。

标志性元素是**信号强度排名**：每个信号旁边写「历史第 3 强 / 共 21 次」，把金额放进该指数自己的历史里定位，而不是给一个孤零零的亿元数字。

## 数据流

```
market.sqlite ──ingest.py──> data/ (git) ──astro build──> dist/ (静态站)
```

份额与行情先由 `etf_flow_monitor.py`、`astock sync` 更新进库，然后：

```bash
python3 ingest.py          # 从 sqlite 全量导出 data/（初始化或重建历史时用）
npm run build              # 只读 data/，不碰数据库
```

日常更新不用这台机器：`.github/workflows/daily-data.yml` 周一至五 22:48 和 23:48（北京时间）跑 `daily.py`，抓当天份额与行情、追加到 `data/`、校验构建、提交，EdgeOne 随后自动重建。

```bash
python3 daily.py                     # 抓今天
python3 daily.py --date 2026-10-23   # 补指定日期
python3 daily.py --backfill          # 把每个序列缺的交易日都补上
python3 daily.py --dry-run           # 只看要追加什么
```

`daily.py` 不连数据库：`data/` 自己就是状态，算 Δ份额只需上一交易日的份额，就在 CSV 最后一行。

| 用途 | 源 |
|---|---|
| 沪市份额 | 上交所 commonQuery，一次拿全市场（21:18 后发布） |
| 深市份额 | 深交所 1945 报表，逐只，偶发连接重置，带重试 |
| 当日行情 | 腾讯 `qt.gtimg.cn` 批量快照，一次几十只 |
| 历史补缺 | 腾讯日线 → 新浪日线 → 中证 index-perf（H/930/931 只能走官网） |

不用 baostock：它从境外经常登录失败（`10002007`），而腾讯不复权日线与库内 baostock `none` 实测同值（ETF 33/33 根完全一致，指数最大差 0.005 点）。

**沪市份额只用上交所归档。** 21:18 左右当天快照常常还没发布，`etf_flow_monitor.py` 会回退到同花顺（规模 ÷ 净值反推），那个值来自季报口径，偏低且越拖越偏——2026-10-21~23 三天 47 只沪市 ETF 全部偏低，最多 10%，把 10-23 的合计从 +371 亿写成了 −106 亿。交易所归档里这几天的数据是有的，只是发布得晚。若 sqlite 里某天是 `source='ths'`，先跑：

```bash
python3 tools/resync_shares.py --from 2026-10-21 --to 2026-10-23
python3 ingest.py
```

构建端不连数据库：换机器、上 CI 都能复现，`data/` 的 diff 就是当天数据变化的审计记录。`python3 ingest.py --stats` 只打印每个指数的信号数量，不写文件。

## 数据格式

| 文件 | 内容 |
|---|---|
| `data/indices.json` | 43 个指数 → ETF 映射（人工维护） |
| `data/etfs.json` | 57 只 ETF 元数据（人工维护） |
| `data/meta.json` | 信号参数、折算日、公告锚点、覆盖缺口、K 线滞后标记、每个指数的解析结果（生成） |
| `data/index/<slug>.csv` | `date,o,h,l,c,flow,n_in,n_out,n_etf,scale`，K 线与申赎按图表起点对齐 |
| `data/etf/<code>.csv` | `date,close,share,flow,d_share` |
| `data/events.jsonl` | 信号事件快照，一行一个，按日期升序。含 `rank` / `n_events`（该指数内部按 \|当日金额\| 的排名） |

时序用 CSV、一个序列一个文件：体积比 JSONL 小约 15%，diff 逐行可读，每天只改每个文件最后一行，git 存 delta 后一天只有几十 KB。事件是追加流，用 JSONL。

构建开头会校验：每个 CSV 的最后一行日期必须等于 `meta.latest_trade_date`，对不上直接 fail；K 线确实比份额晚几天的指数必须在 `meta.stale` 里显式声明，页面上也会标出来，不当成「份额没变化」。

## 信号规则

日净申赎 `F = Σ(Δ份额 × 当日收盘价)`，按标的指数加总。

1. `|F| ≥ max(2 亿, 8% × 该指数 ETF 合计规模)`，占比门槛封顶 100 亿；
2. 成分 ETF ≥ 2 只时，同向只数 ≥ `max(2, 60%)`；
3. 每个触发日单独记一条，不合并——连续几天都过门槛就是连续几条信号；
4. 历史排名按方向分开：买点内部比买多少、卖点内部比卖多少，`1` 是各自方向里最大的那次。

已剔除份额折算日（510310 2024-09-20、512100 2022-09-02、560010 2022-09-13）。
深市 10 只 ETF 没有免费的日度份额历史，2026-10-21 起才有，只进当日数据、不进历史序列。

## 部署

腾讯云 EdgeOne Makers。`edgeone.json` 已写好：

- install：`npm ci`
- build：`npm run build`
- 输出目录：`./dist`

控制台导入仓库后**加速区域选「全球可用区（不含中国大陆）」**，绑定自定义域名不需要工信部备案；如果域名已备案，改选「中国大陆可用区」拿到国内节点。

注意：不绑自定义域名时，项目默认域名在中国大陆只能用系统生成的预览链接访问（3 小时过期返回 401），所以必须绑一个自己的子域名。

`data/` 随仓库提交，所以平台只需要 node 环境，不需要数据库。

## 口径与已知限制

- 份额是基金总份额（一级市场申赎），不是成交额——成交额法实测精确率只有 4%。
- 「份额大增」不等于「国家队买入」：2022-12 510300 份额 +82% 时汇金持仓纹丝未动。
- 「大额净赎回」也不等于清仓：2026-01 的 13 个交易日 -7722 亿，同期沪深 300 走平，更像换仓／转托管。
- 沪市份额来自上交所归档接口（2012-01-04 起），覆盖度逐年爬升，跨年比较要按当年在册只数归一。
- 个别指数 K 线滞后于份额（上游行情未补），页面单独标注。
- 信号方向对、强度不够当择时用。

口径细节见站内「口径说明」页，以及 `skills/custom/etf-flow-tracking/`。
